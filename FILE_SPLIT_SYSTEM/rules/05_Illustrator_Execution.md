# 05 Illustrator 执行规则

本文件是本机执行边界、预检、自动化和失败处理的权威规则。

## 1. 工具边界

正式对象编辑、删除、群组、画板建立、文字转曲、保存和导出必须在 Adobe Illustrator 中完成。外部工具仅可用于只读分析、OCR、预览、文件管理、哈希计算和 QA；不得用截图、重绘或整页栅格化替代 Illustrator 对象处理。

ChatGPT 可整理要求和提示词；只有具备本机权限的 Codex 才能执行 Illustrator 操作。云端仓库任务不得假设可控制用户电脑中的 Illustrator，也不得把规则文件已建立表述为自动化已实现或通过。

## 2. 执行前预检

开始编辑前记录并核对：

- 实际操作系统与 Illustrator 版本；
- 可用且已验证的脚本或自动化接口；
- 当前打开文档、用户未保存工作及目标实例；
- 字体、链接图像和其他依赖资源；
- 原稿可编辑性、锁定/隐藏对象、剪切蒙版和转曲状态；
- 文档颜色模式、颜色配置、专色定义和关键色调；
- 逻辑页面或包装面边界；
- 输入文件哈希、处理副本路径、输出和临时目录可写性；
- 画板数量/总宽、导出像素等软件限制。

任何影响外观或边界正确性的缺失项都必须在对象编辑前解决或标为 `needs_review`。

## 3. 工作副本与路径

只在原稿副本上处理，并记录原稿哈希以证明原稿未被覆盖。输入、输出和临时路径通过任务参数或配置提供，必须支持中文、空格和不同磁盘；不得写死桌面、案例目录或当前操作者用户名。

相同名称的不同输入放入不同任务目录，避免中间文件相互覆盖。最终文件仍遵循分支命名规则。

## 4. 自动化原则

优先使用经过目标 Illustrator 版本验证的脚本接口，减少窗口激活、弹窗和鼠标键盘模拟。不得关闭用户其他文档、覆盖未保存工作或强制退出 Illustrator。

同一 Illustrator 实例的编辑任务串行运行。若确需处理交互弹窗，记录弹窗内容、触发步骤和所需用户动作；不得伪称任务仍在后台成功运行。

不保证 Illustrator 完全无界面或绝不抢焦点。后台运行能力作为独立验证项，只有在实际系统、版本和接口上完成测试后才能标记通过。

## 5. 阶段检查点与重试

至少保存以下阶段检查点：`preflight_complete`、`analysis_complete`、`working_copy_opened`、`content_edited`、`artboards_or_faces_built`、`export_complete`、`qa_complete`。每项记录时间、状态、产物或证据及错误。

重试前读取任务记录并检查当前文档状态，确认哪些删除、移动、转曲或导出已经完成，避免重复删除、重复移动和重复转曲。不能确认状态时，从未修改的工作副本重新开始，而不是在未知状态上继续。

## 6. 限制与失败

若画板总宽、画板数量、导出像素尺寸、内存或其他实际软件限制被触发，停止受影响步骤并报告具体限制。不得自行缩放内容、改成多行、降低清晰度或变更交付格式。

字体缺失、链接缺失、色样冲突、对象不可编辑、边界不明或弹窗阻断时，记录问题、受影响范围和已完成阶段。可安全继续的其他文件不受阻断。

状态使用：`pending`、`classified`、`analyzed`、`processing`、`exported`、`qa_passed`、`needs_review`、`failed`。只有全部必需 QA 通过后才能使用 `qa_passed`。
