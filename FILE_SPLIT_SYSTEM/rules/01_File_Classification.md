# 01 文件识别与自动分类

本文件是输入角色、任务类型、型号和路由的权威规则。

## 1. 分类单位与文件角色

每个输入文件独立分类。批量任务中允许不同原稿进入不同分支，不因同批提交而强制统一类型。

先判断文件角色：

- `source`：需要正式处理的原稿。
- `reference`：用户提供的参考成品、效果图或核对材料，不再次作为原稿处理。
- `supporting`：字体、链接图像、色样说明等辅助资源。
- `unknown`：证据不足，必须记录待确认项。

参考 PNG/PDF 与原稿可能名称相近，必须结合用户说明、文件内容、尺寸、创建关系和是否呈现最终组合效果判断角色。

## 2. 证据采集

不得只按扩展名或单一关键词分类。PDF、AI 等格式都可能承载说明书或包装。至少综合检查：

- 文件名及用户描述；
- 可提取文字、章节和语言结构；
- 物理页与逻辑页面布局；
- 矢量对象、页面边框、画板或裁切框；
- 刀模、折线、折翼、粘口和多个盒面；
- 尺寸标注、工艺说明、辅助色块或 UV 副稿；
- 预览和 OCR 结果。

OCR 仅辅助识别，不能重建正式内容。已转曲文件无法提取文字不等于空白，必须结合可见对象和结构检查。

## 3. 分支证据

`WEB_MANUAL` 的主要证据包括：连续阅读页面、多语言正文、语言页码、封面/封底、使用步骤、安全说明和说明书章节结构。

`PACKAGING_DISPLAY` 的主要证据包括：刀模展开结构、多个包装面、折线、折翼、粘口、印刷工艺标注、尺寸标注和 UV 副稿。

以下证据不得单独决定分类：

- 条码或二维码：说明书封底也可能包含。
- `WARRANTY POLICY`：包装也可能出现。
- 无可提取文字：文件可能已经转曲。
- 文件名中的“说明书”“包装”字样：只能作为证据之一。

## 4. 用户指定与冲突

用户明确指定文件用途时优先遵循。若实际内容明显矛盾，记录可复核的具体问题，例如“用户指定为说明书，但文件包含完整刀模、折翼及六个盒面且无连续阅读页面”，将该文件设为 `needs_review` 并询问；不得静默覆盖用户指定。

同一原稿混合两类内容、型号冲突、页面/包装面边界无法可靠确定时，暂停该文件的编辑。其他证据明确的文件继续执行。

## 5. 型号识别

型号必须从正文、封面/包装主面及文件名交叉确认。优先采用多个独立位置一致出现的产品型号。

不得把日期、版本号、尺寸、电池型号、条码编号或文件流水号当作产品型号。候选值冲突时保留全部候选及其位置；无法确定时将正式目标文件名留空或使用任务内部临时名，不得编造正式型号。

## 6. 必需记录

分类完成后，任务记录至少包含：

- 输入文件和文件哈希；
- 文件角色；
- 分类结果；
- 型号与证据位置；
- 支持和反对该分类的依据；
- 不确定项；
- 后续分支；
- 状态 `classified`，或在存在影响正确性的未决项时标为 `needs_review`。
